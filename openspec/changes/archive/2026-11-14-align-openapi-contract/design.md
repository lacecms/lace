## Context

See proposal.md for the motivation. Facts that shape the approach:

- **Generation.** The document is generated by hono-openapi 1.3.3
  `openAPIRouteHandler` in `packages/server/src/routes/docs.ts`. The
  committed artifact is written by `apps/api/scripts/generate-openapi.mjs`
  and checked for staleness by `pnpm openapi:check`.
- **The default `400`.** hono-openapi adds `DEFAULT_VALIDATION_ERROR` to
  every operation that uses `validator()` unless the spec options set
  `defaultValidationErrorResponse: false`.
- **Validation hook.** It always returns `validationResponse(...)`, which is
  `422 VALIDATION_FAILED` in the shared envelope (`shared/http.ts`).
- **Hand-parsed queries.** The public `collections`, `records` and
  `content/by-path` routes read `after`/`limit` through `pagination()` and
  `path` by hand.
- **Denials.** A missing actor throws `AuthorizationError`, and the classifier
  maps it to `403` (`contracts/src/errors/classification.ts`). No error code
  maps to `401`.
- **Credentials.** The build export reads `Authorization: Bearer`. Import
  tokens use Bearer on the routes allowed by `security/import-routes.ts`
  `isImportRoute`. Browser sessions use the Better Auth session cookie.

## Goals / Non-Goals

**Goals:**

- The document describes enforced behavior.
- One test keeps the document honest.

**Non-Goals:**

- Changing any status code, parser or validation message. The existing route
  tests must pass unchanged.

## Decisions

### D1. Disable the default and document `422` once

`openAPIRouteHandler` receives `defaultValidationErrorResponse: false`. A
server helper `validationFailure` returns the documented `422` response object
(the envelope via `resolver(errorEnvelopeSchema)`). Every route that uses
`validator()` or a hand parser spreads it into `describeRoute({ responses })`.

*Alternative rejected:* the `describeRoute` default options in
`GenerateSpecOptions`. They would add `422` to routes that validate nothing,
which is also wrong.

*Alternative rejected:* post-processing to rename `400` to `422`. It hides
the source of truth and breaks when hono-openapi changes its default.

### D2. Document hand-parsed parameters without changing parsing

The three public reads declare `parameters` in `describeRoute`:

- `after`: an opaque cursor string;
- `limit`: an integer from 1 to `MAX_PAGE_SIZE`, defaulting to
  `DEFAULT_PAGE_SIZE`;
- `path`: a required string.

The limits come from the `@lacecms/contracts` constants. `pagination()` and
the by-path parsing stay as they are, so error paths (`/limit`, `/after`,
`/path`) and messages do not change.

*Alternative rejected:* switching to `validator("query", …)`. It would change
issue messages and reject unknown query keys.

### D3. Replace `401` with the classified `403`

The seven `401 "Session required"` entries become one shared `403` response
from the `authorizationFailure` helper ("Authentication or permission
required"). Each operation that resolves an actor or verifies a token uses
it. Operations that already document a different `403` meaning (for example
"Invalid origin") merge both into one description.

### D4. Security schemes from the existing boundaries

`documentation.components.securitySchemes` declares:

- `session`: `apiKey` in a cookie named `better-auth.session_token`, with a
  note that the secure-prefixed name applies over HTTPS;
- `buildToken`: `http`/`bearer`;
- `importToken`: `http`/`bearer`.

Each `describeRoute` states `security` explicitly:

| Routes | `security` |
| --- | --- |
| public reads | `[]` |
| build export | `[{buildToken: []}]` |
| admin and account routes | `[{session: []}]` |
| routes where `isImportRoute` is true | `[{session: []}, {importToken: []}]` |
| `GET /admin/import-credential` (allowlisted, refuses a session) | `[{importToken: []}]` |
| invitation and password-reset completion | `[]`, because the token travels in the body |

A test cross-checks the import annotation against `isImportRoute`, so the
allowlist stays the single owner.

*Alternative rejected:* deriving `security` by post-processing path
prefixes. That logic would be a second policy table beside the real one.

### D5. Contract test over the generated document

A new `packages/server/src/routes/openapi-contract.test.ts` builds the app
with the same inputs as `generate-openapi.mjs` and fetches
`/api/v1/openapi.json`. The test:

1. Lists registered routes from the Hono router (`app.routes`), limited to
   `/api/v1/*` and excluding `/api/v1/openapi.json`.
2. Asserts, for each route:
   - the operation exists with a summary and a tag;
   - it documents no description `"Validation Error"` and no `400`, except
     the classified `400 INVALID_CREDENTIALS` of `POST /account/password`;
   - it documents no `401`;
   - it documents `422` when the route has a validator or a hand parser;
   - it has an explicit `security` array.

   A hand parser is recorded in a small explicit set in the test.
3. Asserts the scenarios of the delta spec: a `201` for token creation, the
   public query parameters, and the declared schemes.

Failures name the method and path. `pnpm openapi:check` keeps guarding that
the committed artifact is current.

### D6. One `ErrorEnvelope` component (apply-time)

`docs.ts` names `errorEnvelopeSchema` `ErrorEnvelope` through the existing
`overrideSchema` hook and adds the component, derived with
`toJsonSchema`. Every error response references it instead of inlining the
schema; the component equals the former inline schema. No contracts change is
needed. The contract test asserts every documented `403` and `422` uses the
reference. The MCP-connection OpenAPI assertions in `protocol.test.ts` pin
documented statuses, so they move from `401` to `403`; no runtime assertion
changes.

## Risks / Trade-offs

- **[Risk]** Clients generated from the old document change their error
  types. → This is a correction toward actual behavior. The changelog for the
  next release states it.
- **[Risk]** The fixed cookie name can drift from the Better Auth
  configuration. → The scheme description names the prefix rule. The cookie
  name is already asserted by platform-node tests.
- **[Trade-off]** The hand-parser set in the test is maintained by hand.
  Moving those routes to `validator()` is left for a later change (see
  non-goals).

## Migration Plan

Regenerate and commit `apps/api/openapi/api-v1.json`. No deployment step is
needed. The served document changes with the next engine release.
