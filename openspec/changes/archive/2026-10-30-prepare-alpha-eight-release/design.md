## Goals / Non-Goals

**Goals:** one coherent alpha.8 graph, actionable upgrade documentation and fresh evidence bound to immutable saved bytes, preserving existing Node/Cloudflare semantics and security boundaries.

**Non-Goals:** redesign release tooling or accepted features, add dependency upgrades unrelated to a demonstrated gate failure, publish/deploy, relax audit policy, delete older outputs or implement deferred video uploads.

## Decisions

1. **Advance all coordinates together to alpha.8/template 0.39.0.** Update the release definition, sixteen public manifests, generated dependency references, platform version modules, Docker defaults, registry requirements and delivered versioned commands. Keep private packages private. Add alpha.7 to published history; do not retrofit MCP into alpha.7's inventory. Refresh the lockfile, template upgrade metadata and six generated snapshots. The template increment captures release guidance and MCP deployment changes without rewriting historical template instructions. Rejected: only changing the release JSON, reverting to template 0.35.0 or reusing alpha.7 saved artifacts.
2. **Treat documentation as part of compatibility.** Refresh architecture release references and compatibility guidance before downstream prose. Root changelog has 3–6 concise bullets with a permanent alpha.8 upgrade link. Public catalog, version assertions, topic pages, internal operations and generated guides stay coherent. Cover list settings, compact rows, video adoption, Link/component updates, format-2 exports, collection-query runtime bounds, MCP client setup and opt-in activation. No new runtime behavior or migration is introduced by this release session.
3. **Reuse existing package boundaries and acceptance machinery.** `scripts/release-model.mjs`, release preparation/verification, publication/lifecycle tests and the generated consumer harness remain authoritative. Packages own their runtime assets; tests must not add runtime coupling or workspace imports to consumer projects. Existing MCP compatibility, lifecycle, bundle and Worker tests provide source evidence. Extend saved-artifact journeys with a dedicated alpha.8 helper as needed, exercising the inventory's generator, archives and images on Node and the generated local Worker. The helper must not resolve source-workspace runtime code. Cover migrations, MCP's default-off and enabled flows, proxy discovery/transport, consent, draft changes and revocation alongside format-2 links, embeds, list settings and query behavior. Label source-only concurrency/replay/D1-budget checks separately.
4. **Freeze source only after source gates and audit pass.** Use the installed pinned Node 24.12.0 and pnpm 12.3.4, frozen dependencies and the existing security/license policy. Fix demonstrated release regressions within accepted semantics; stop for design/scope changes or a new audit-policy decision. Commit reviewed shipping changes as the concrete prerequisite to clean-source preparation, verify status and use `.release-artifacts/alpha-8` or an explicitly recorded distinct retry path. Never overwrite inventories or successful receipts; preserve existing artifact locks and provenance rules.
5. **Separate preparation from publication and remote deployment.** Run complete two-platform preparation, independent verification and exact-artifact acceptance with durable sanitized reports. Handoff records source/fingerprint, inventory checksum, archive hashes, local image IDs, harness revision and actual coverage. Local Worker/D1/R2 and Pages configuration checks are not a real Cloudflare deployment. npm/GHCR/GitHub publication requires a later explicit owner request; no publication credentials are needed to prepare locally.

## Risks / Trade-offs

- Format-2 export and new source renderers require coordinated adoption → document and test old/new boundaries, unavailable links and conflict-aware component updates.
- New OAuth graph increases packaging and runtime initialization risk → run compatibility/type fixtures, saved image and Worker flows, scope/role/revocation checks and default-off regression; preserve credential redaction in diagnostics and proxy logs.
- Migrations and configuration sync can make a package-only downgrade unsafe → verify the four shipped migrations on SQLite/D1 and require matching backups/configuration/media/site source for rollback; retain atomicity and existing forward-only behavior.
- Historical tooling assumes fifteen packages or alpha.7 journeys → update active inventory-count assertions and add alpha.8 coverage, preserving historical fixtures and reports where fifteen remains correct.
- Docker, registry, audit or acceptance failures can block readiness → retain precise failed/unavailable gates and sanitized evidence, continue independent work and rebuild only into a distinct output. Do not weaken readiness criteria.
