## Context

See the proposal. The CLI manifest exposes `index.ts` and `bin.ts`; `index.ts` currently owns parsing, error/types, environment and presentation while importing a diagnostic type, and `diagnostics.ts` imports the entry. Several packaged tests import individual built modules, and the schema generator and registry loader assume current `dist` locations. The build currently includes only `src/*.ts`; moving source without widening it silently omits nested modules.

## Goals / Non-Goals

**Goals:** Enforce the existing §6 layout for CLI, retain source and packaged coverage, and keep observable behavior and public exports stable.

**Non-Goals:** Change error classification, operator safety, command semantics, registry contents, dependency graph between packages, or type all existing CLI tests (RF9F).

## Decisions

1. Move concrete modules into concern directories for shared primitives/flag parsing, operator commands and transports, diagnostics/doctor/preflight, blocks, import and upgrade. Keep only manifest entries and package-level tests at the root; colocate module tests. Document actual one-way directory edges in the entry header and `scripts/source-layout.json`. Choose precise directory names and edges from the moved graph rather than forcing an artificial hierarchy. Split shared types/errors and diagnostic vocabulary into lower-level modules so internal code imports concrete modules, never the entry point. Remove the CLI cycle baseline entry only after the complete graph is acyclic, including type imports. Avoid subdirectory barrels. Leaving the cycle baselined or putting all files in one directory would not deliver §6.
2. Keep root `index.ts` as explicit re-exports of its current public names and root `bin.ts` as executable entry. Widen TypeScript build inclusion to nested source while excluding tests and test-support. Update all direct source, built-module, scripts, verification and fixture references after moves, including paths embedded in subprocess code and URL computations. Keep `dist/bin.js`, the root public export, schema and `dist/registry/` unchanged. Resolve registry relative to its new compiled module location and exercise the real bundled bytes; do not assume its former `import.meta.url` base. Internal deep paths are not package exports, but repository consumers must be updated together.
3. Convert `import-api`, `import-fixtures`, and `upgrade-fixtures` to typed test-support modules without `@ts-nocheck`, updating all consumers, including `.packaged.test.mjs` files and any subprocess references. Packaged tests still exercise built production modules under the existing packaged configuration; TypeScript test helpers are test infrastructure, not shipped output. Update only corresponding JavaScript allowlist and test-typecheck baseline paths as appropriate; do not mask new exceptions or expand RF9F's test-typing scope.
4. Share one CLI-local predicate for identical non-null, non-array record checks, retaining narrower JSON typing through a correctly typed wrapper or overload where needed. Do not conflate predicates with different semantics (e.g. checks for a property or prototype), nor add a production `@lacecms/content` import. For scaffolding, derive the closed field-type vocabulary through an already permitted public type where possible, or a locally checked structural type tied to it; handle every supported case explicitly, including those currently sharing default markup. Preserve runtime validation/fallback behavior for untrusted input and generated bytes. An unconstrained string plus catch-all does not provide compile-time exhaustiveness.
5. Correct the duplicate RF9F helper assignment when recording RF7C completion; retain the remaining RF9F test typing. Keep all behavioral requirements in the existing accepted specs, so this change has no spec delta.

## Risks / Trade-offs

- [Move breaks packaged or generated paths while source tests pass] → Build and run packaged tests, schema generation and bundled-registry checks, plus binary/help and lazy Cloudflare tests; inspect subprocess paths and repository references.
- [Helper conversion changes test resolution or leaks into package output] → Run both test configurations and typecheck; inspect packed/build output and keep test-support excluded from production compilation.
- [Scaffold exhaustiveness changes handling of malformed data or emitted markup] → Preserve existing input-boundary behavior and assert existing cases and all supported field types with representative byte/output checks.
- [Directory graph introduces hidden cycles or exceptions] → Run the existing boundary checker and remove only stale CLI baseline/allowlist entries; do not weaken guards.

## Migration Plan

No data or user migration is needed. Ship as a single coherent source move and build/test update; revert the change together if needed. Published manifest exports and binary locations stay stable.
