## MODIFIED Requirements

### Requirement: Upgrade from the latest published template is proven

The repository SHALL keep fixtures holding the exact default and `--cloudflare` projects generated by the generator of the latest published release (today `create-lace@0.1.0-rc2`, template `0.47.0`, the oldest supported release), recording that package's published digests and source revision, and a test SHALL verify each retained fixture's manifest version, provenance and managed-file digests without naming a template version in the test. Fixtures of earlier templates SHALL NOT be kept once a later published template has fixtures. Acceptance SHALL materialize each fixture, add a user README and user edits to `lace.config.ts` and a `site/` source file, generate the current template with the same options, and upgrade with the packed CLI:

- a modified managed file SHALL be reported as a conflict, and apply SHALL fail without changing any project file other than its conflict-review and recovery records under `.lace/`;
- after the operator restores that file, the plan SHALL have no conflict, apply SHALL make every changed or new managed file equal the current template, remove a retired managed file that was unmodified, record the current template version, and leave the README, `lace.config.ts` and all `site/` files byte-for-byte unchanged without adding files under `site/`;
- a following plan SHALL report no changes.

Each fixture SHALL be generated from the actual immutable published package
with recorded source revision, archive hash and registry integrity, never
reconstructed from the current workspace. Generic upgrade conflict,
user-file preservation, digest-tampering, recovery, idempotence and
image-identity tests SHALL remain when fixtures are replaced.

#### Scenario: Published-template project upgrade
- **WHEN** a project on the latest published template with user edits is upgraded to the current template
- **THEN** managed infrastructure is current and the user's README, configuration and site source are unchanged

#### Scenario: Modified managed infrastructure
- **WHEN** a managed file of the published-template project was edited by the operator
- **THEN** the upgrade reports the conflict and apply writes nothing

#### Scenario: Fixture integrity
- **WHEN** a retained fixture's managed file bytes no longer match the digests in its recorded manifest
- **THEN** the fixture test fails naming the fixture and file

#### Scenario: rc2 fixtures replace the rc1 fixtures
- **WHEN** the fixture directories are listed after rc2 became the oldest supported release
- **THEN** only the default and `--cloudflare` fixtures of template `0.47.0` from `create-lace@0.1.0-rc2` remain, and no template `0.46.0` fixture is kept
