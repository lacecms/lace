## Why

Roadmap Step 32, session **32A — Independent consumer regressions**. Steps
26–31 resolved the onboarding feedback (`docs/onboarding-feedback.md` §1–§12)
one session at a time, and each fix is proven by its own acceptance phase. They
have never been proven together in the consumers that matter: the default
`pnpm acceptance:generated` run still writes `.env` by hand, creates the first
administrator through the API, never shows the introductory tour, and does not
include publication visibility, the existing-site consumer or any upgrade from
the published alpha template. Before 32B refreshes the next alpha artifact set,
the feedback must be closed by passing regressions, not by a list of earlier
session claims.

## What Changes

- The full generated-project acceptance (`pnpm acceptance:generated`, phase
  `all`) becomes the feedback regression suite. It fails on the first
  unresolved defect and refuses the publication-visibility observe-only mode.
- **Generated Node consumer, README-driven.** The suite reads the generated
  README's installation and "Prepare and start the CMS" command blocks, fails if
  they differ from the reviewed sequence, and executes that sequence: packed
  install, `pnpm env:prepare` (only the documented review settings are then
  edited), `lace doctor --stage setup`, `pnpm db:migrate` with no pre-created
  database directory, `pnpm content:sync`, `pnpm auth:bootstrap` and
  `pnpm dev:api`. The first administrator is created in a real browser through
  the setup screen; the administrator signs in, completes the introductory tour
  (permitted steps, persisted completion, replay) and uploads media in the
  packaged admin. Publication, build token, Astro build with media bytes, the
  Compose production release and dev/manual/automatic publication visibility
  follow against the same installation.
- **Existing-Astro consumer.** The existing-site journey (CMS generated in
  `cms/` with `--existing-site ..`) follows the generated connection guide:
  its loader, type declaration and route files are taken from the guide's code
  blocks, blocks are installed with `lace add block --all --site ..`, and the
  resolved Compose configuration must select the parent site read-only as the
  build site. The build must render all five blocks with styling hooks, escape
  hostile rich text, refuse an unsafe link, and return the public media bytes
  through browser-facing URLs. An operator edit to a block component survives
  both a repeat install and a simulated block update, which instead updates the
  unmodified component and reports the edited one as a conflict.
- **Cloudflare consumer.** The Step 31 packed Cloudflare journey (setup-stage
  doctor, expired token and re-issue, unavailable then recovered deploy hook,
  restart persistence) stays part of the suite.
- **Upgrade from alpha template `0.4.0`.** Committed fixtures hold the exact
  default and `--cloudflare` projects generated by the published
  `create-lace@0.1.0-alpha.1` tarball. The suite upgrades them with the packed
  CLI to a freshly generated current template: a modified managed file is a
  conflict that blocks apply without writing; after restoring it, apply updates
  the changed managed files, adds new managed files, removes the retired
  Cloudflare root `wrangler.jsonc`, preserves a user README, `lace.config.ts`
  and every `site/` file byte-for-byte, and a repeat plan has no changes.
- **Feedback traceability.** New `docs/onboarding-feedback-acceptance.md` maps
  every feedback item to acceptance stages, tests and documents, or to an
  explicit decision/deferral. §11 stays deferred. A repository test fails when a
  feedback item is unmapped, a referenced stage/file does not exist, or an
  unresolved defect is listed.
- New pure-helper unit tests for README command extraction, guide file
  extraction, environment review edits and fixture integrity.
- Roadmap Step 32 marks 32A delivered scope.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `generated-project-acceptance`: the full run becomes the feedback regression
  suite: README-driven Node setup with browser bootstrap and tour, visibility,
  the existing-Astro consumer contract, the Cloudflare journey, upgrade from
  template `0.4.0`, and machine-checked feedback traceability.
