## MP1 verification

### Baseline on 2026-11-24

Ran [the Chromium acceptance script](../../../../scripts/admin-media-thumbnail-acceptance.mjs)
against the original admin and an isolated Node/SQLite and pinned SILO
installation. The script seeds 120 active images, including a legacy JPEG with
EXIF orientation 6 and a NULL hash, a large JPEG and PNG, a translucent PNG,
an AVIF and red/blue GIFs. The large GIF measures 2048 × 1536 with 36 frames,
for 113.25 megapixels across its frames.

The viewport was 1440 × 900. The script scrolled in six-item increments through
each batch before activating Load more media. After the final batch it filtered
by the small GIF's filename and opened the details panel. The original preview
was already loaded by the grid and Chromium reused it when opening the panel.

| Displayed | Cumulative original browser requests | Cumulative image body bytes |
| ---: | ---: | ---: |
| 50 | 50 | 23,724,519 |
| 100 | 100 | 33,482,619 |
| 120 | 120 | 37,385,859 |

The baseline JSON and screenshots are stored locally in
`.lace-acceptance/admin-media-thumbnails/`.

### Application and private storage

The focused application suite exercised 20 cases, including lost put
acknowledgment, timeout and retry and a 24-item burst. The
[storage acceptance](../../../../tests/media-thumbnail-storage.acceptance.mjs)
passed with the pinned SILO image and local native R2 bindings. Two writers
using different WebP bytes produced one winner per provider. Fresh services
returned the winner's bytes and digest without reading the original. Both
adapters listed only the thumbnail prefix and accepted repeated deletion.

### Image transformation

Five local acceptance tests exercised Sharp and an injected Worker Images
binding. Both compositions produced 24 valid thumbnails in one burst. The
tests decoded the first GIF frame and transparent PNG, checked EXIF
orientation and uncropped output, exercised the missing-binding and invalid
output paths, and cancelled an unfinished provider response.

Pinned Wrangler 4.162.0 bundled the Worker probe with only an Images binding.
An isolated Cloudflare remote preview, started and stopped on 2026-11-24,
ran the actual adapter and portable validation. All files were generated by
the fixture. The timings include loopback transport and preview overhead.

All responses were 200 with single-frame WebP. The PNG retained alpha and
both GIFs decoded to red on the first pixel (228, 19, 28). The large GIF
exercised 113.25 MP across frames. AVIF worked on the tested account.
Cloudflare's [published input limits](https://developers.cloudflare.com/images/get-started/limits/)
describe plan and format restrictions that may differ by deployment.

### Upload and deletion lifecycle

Node and Worker HTTP uploads returned while committed background work was
paused. A simulated interruption was repaired on demand, and a rolled-back
write started no work. Tests with real SILO and local R2 verified deletion
order, retry, absent derivatives and cleanup after a put settles following
deletion. The persisted cursor resumed in a fresh adapter after deleting keys
from the previous page. Active owners and a failed SQL read preserved their
objects. Worker mixed-dispatch and maintenance tests kept the existing
50-query D1 budget with a thumbnail pass.

### HTTP, Admin and adoption

The session route passed the permission, lifecycle and conditional request
tests. Original admin and public binaries passed their existing tests.
`pnpm openapi:generate` and `pnpm openapi:check` matched the new artifact.
The latter used an isolated Git index containing the generated artifact.

The 112 focused Admin tests passed. A Chromium test also substituted a 503
for the GIF thumbnail in grid and list, observed zero original requests while
browsing, and saw both red and blue frames after opening the original.

The public docs check and all 45 generator tests passed. Six generated project
layouts were regenerated twice, and the packed upgrade journey from template
0.50.0 preserved the operator's Wrangler file. The real preview verified
`images.binding` with pinned Wrangler. A missing binding kept the original
readable, and fresh Node and Worker installs restored from original-only
backups generated a missing WebP with a stable validator on the first read.

### Candidate Chromium runs

Ran `node scripts/admin-media-thumbnail-acceptance.mjs` with the same
120 images, 1440 × 900 viewport and six-item scroll increments as the
baseline. Node used SQLite, pinned SILO and Sharp. The local Worker used
D1, R2 and the deterministic Images binding test double. The real provider
run is recorded separately above. Each cold run started with empty derivative
storage. Each warm run used a fresh runtime over the same stored thumbnails
and a fresh browser context with its HTTP cache disabled.

| Runtime and state | First 24 body bytes | All 120 body bytes | Browser originals while browsing | Original reads / transformations while browsing | First batch / full browse (ms) |
| --- | ---: | ---: | ---: | ---: | ---: |
| Node, cold | 568,720 | 3,585,616 | 0 | 120 / 120 | 417 / 1,984 |
| Node, stored | 568,720 | 3,585,616 | 0 | 0 / 0 | 254 / 1,387 |
| Worker, cold | 568,720 | 3,585,616 | 0 | 120 / 120 | 600 / 2,952 |
| Worker, stored | 568,720 | 3,585,616 | 0 | 0 / 0 | 405 / 1,857 |

All four runs showed 24, 48, 72, 96 and 120 items with one explicit action
per continuation. Each requested 120 thumbnails over five batches. First-batch
bodies measured 0.54 MiB against the 2.25 MiB cap. For all 120 items, image
bodies fell from 37,385,859 to 3,585,616 bytes. Filtering restarted at the first
page and opening the GIF made one original preview request. Timings include
the scripted browser interactions and reflect local observations.

The picker loaded 24 choices and appended 24 while retaining the selected
GIF. An intercepted 503 displayed the fallback both in the picker and in the
collapsed editor row. Neither surface requested the original. The five
Playwright picker tests passed, including the accessibility checks at 320 px
in light and dark modes. The editor header actions wrap on narrow screens
to keep the page within the viewport.

JSON measurements and Chromium screenshots are in
`.lace-acceptance/admin-media-thumbnails/`. Run the script with `baseline`
against the original admin to reproduce its measurements.
